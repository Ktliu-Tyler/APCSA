Lesson Flow

本課路線

Receiver Object

Instance method 永遠要先知道「哪個 object 接收這次 call」

Receiver Method Call

Student s = new Student("Amy", 95);

s.setScore(80);

在 s.setScore(80) 中，s reference 的 object 就是 receiver object。 setScore 對那個 object 執行，80 是 argument。 

s
│
└── receiver object
    name = "Amy"
    score = 95

s.setScore(80)
    mutates receiver.score

Receiver State

同一份 method code，可以作用在不同 objects 的不同 state 上

Same Method, Different Receivers

Student a = new Student("Amy", 95);
Student b = new Student("Ben", 70);

System.out.println(a.getScore());
System.out.println(b.getScore());

a.getScore() 裡的 score 是 a object 的 score。 b.getScore() 裡的 score 是 b object 的 score。

在 instance method 中，沒加物件名稱的 field，例如 score，通常代表 this.score，也就是 receiver object 的 field。

Return vs Side Effect

Return value 和 side effect 是兩種不同結果

Method 有 return value？ 修改 state？
public int doubledScore() { return score * 2; } 有 否
public void doubleScore() { score *= 2; } 無 有
public int incrementAndGet() { count++; return count; } 有 有

Return vs Mutation

public int add(int x)
{
    return value + x; // no state change
}

public void addToValue(int x)
{
    value += x;       // side effect
}

Pass-by-Value

Java always passes by value

Primitive variable 的 value 是資料本身。Reference variable 的 value 是 reference。 所以 object parameter 得到的是「reference value 的 copy」，不是整個 object 的 copy。

Parameter kind copy 的是什麼？ 可能共享 object？
Primitive 數值本身，例如 5 否
Object reference reference value 是，parameter 和 caller reference 可指向同一 object 
Student s -> Student object

changeScore(s)

parameter st gets a copy of s's reference

s  -> same Student object
st -> same Student object

Object Parameters

Object parameter 可以 mutate caller 也看得到的 shared object

Object Parameter Mutation

public static void changeScore(Student st)
{
    st.setScore(100);
}

Student s = new Student("Amy", 95);
changeScore(s);
System.out.println(s.getScore());

Output 是 100，因為 st 和 s 暫時 reference 同一個 Student object。 st.setScore(100) 修改的是 shared object。

Mutation vs Reassignment

改 object 外面看得到；改 parameter 本身外面看不到

Reassignment Does Not Change Caller Reference

public static void replace(Student st)
{
    st = new Student("Ben", 50);
}

Student s = new Student("Amy", 95);
replace(s);
System.out.println(s.getScore());

Output 仍是 95。st = new Student(...) 只改 local parameter st 的 reference，不會改 caller 變數 s。

Mutationst.setScore(100)：改 shared object。
Reassignmentst = new Student(...)：只改 local parameter。

Aliasing

b = a copy reference，不是 copy object

Alias Trace

Student a = new Student("Amy", 95);
Student b = a;

b.setScore(70);

System.out.println(a.getScore());

Output 是 70。a 和 b 是 aliases：兩個 reference variables 指向同一個 object。透過 b 修改 object 後，透過 a 也看得到。 

a ─┐
   ├──> same Student object
b ─┘       name = "Amy"
           score = 70

Object Return

Return object 時，回傳的是 reference value

Returning Existing Object

public class Team
{
    private Player captain;

    public Player getCaptain()
    {
        return captain;
    }
}

getCaptain() 回傳 captain field 裡的 reference value copy。 Caller 可能和 captain field alias 同一個 Player object。

Return 意思
return captain; 回傳 existing object 的 reference，可能 alias。
return new Player(name); 建立並回傳 new object reference，通常不 alias 原本 object。

Object Parameters In Instance Methods

Instance method 可以同時涉及 receiver 和 object parameter

Transfer Between Objects

public class BankAccount
{
    private double balance;

    public void deposit(double amount)
    {
        balance += amount;
    }

    public void transferTo(BankAccount other, double amount)
    {
        balance -= amount;
        other.deposit(amount);
    }
}

在 a.transferTo(b, 20) 中，receiver 是 a object； object parameter other reference b object。 這個 method 會同時修改兩個 objects。

Method Contracts

FRQ 中，method contract 決定你該 return 還是 mutate

Contract phrase 代表你要注意
returns... Return type 與 return value 語意。
updates / changes / adds / removes... Side effect：哪個 object state 會被改。
Precondition 題目保證的情況，不要多做不必要處理。
Postcondition Method 執行後必須成立的狀態。

Contract Example

public int addBonus(int bonus)
{
    score += bonus;
    return score;
}

這個 method 同時有 side effect 和 return value。AP 題要看 specification 說 method 應該造成什麼效果。

Trace Strategy

Reference tracing 標準流程

1. Count new每個 new 通常是一個 object。
2. Draw arrows每個 reference variable 指向哪個 object。
3. Mark aliasesb = a copy reference。
4. Find receiver點左邊是哪個 object。
5. Copy parametersprimitive value 或 reference value copy。
6. Separate effectsmutation 改 object；reassignment 改 local variable。

Common Errors

本課常見錯誤

錯誤 修正想法
把 Java 說成 pass-by-reference Java always passes by value；object parameter 得到 reference value copy。
以為 object parameter 是 object copy 不是 copy object；parameter 和 caller 可能 reference same object。
以為 reassign parameter 會改 caller variable Reassignment 只移動 local parameter arrow。
看到 return method 就以為沒有 side effect 要看 body；method 可以先 mutate 再 return。
以為 getter 永遠安全 若 getter return mutable object reference，caller 可能 alias 並 mutate。
混淆 receiver 和 object parameter 點左邊是 receiver；括號裡傳入的是 argument。

考前必背十二句

Instance methods run on a receiver object.

Unqualified instance variables belong to the receiver object.

Return value and side effect are different ideas.

Java always passes by value.

An object variable stores a reference value.

An object parameter receives a copy of the reference value.

Mutating the object can be observed through aliases.

Reassigning a parameter does not reassign the caller's variable.

b = a copies a reference, not an object.

Each new creates a new object.

Returning an existing object reference can create aliasing.

Method contracts tell you what to return and what state to modify.
