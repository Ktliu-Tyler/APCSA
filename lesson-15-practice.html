A. Concepts

概念確認

先確認你能用精準語言說明 instance method、receiver、reference 與 aliasing。

Q1Instance Method

什麼是 instance method？

Instance method 是在某個 object 上呼叫的 method，通常可以讀取或修改那個 receiver object 的 instance variables。

Q2Receiver Object

在 s.getScore() 中，哪一個是 receiver object？

s 是 receiver object。意思是：在 s 指到的那個 Student object 上執行 getScore。

Q3Same Method Code

同一個 method code 可以在不同 object 上產生不同結果嗎？為什麼？

可以。因為每次 method call 都有自己的 receiver object，method 讀到的是那個 object 的 instance variables。

Q4Return vs Side Effect

Return value 和 side effect 的差別是什麼？

Return value 是 method 回傳給 caller 的值；side effect 是 method 改變了某個 object 的 state，例如修改 instance variable。

Q5Pass-by-Value

Java 的 parameter passing 規則是什麼？

Java always passes by value。Primitive parameter 拿到 primitive value 的 copy；object parameter 拿到 reference value 的 copy。

Q6Aliasing

Student b = a; 代表複製 object 嗎？

不是。這是複製 reference value，讓 a 和 b 指向同一個 object，因此形成 aliases。

B. Receiver / Side Effect

Receiver object 與 state trace

Instance method 題目要先找 receiver，再判斷 method 是否改變 state。

Q7Trace

以下程式印出什麼？

Student a = new Student("Ada", 80);
Student b = new Student("Ben", 90);
System.out.println(a.getScore());
System.out.println(b.getScore());

印出 80 再印出 90。兩次呼叫的 receiver object 不同，所以讀到不同 object 的 score。

Q8Mutation

以下程式最後印出什麼？

Student a = new Student("Ada", 80);
Student b = new Student("Ben", 90);
a.setScore(75);
System.out.println(b.getScore());

印出 90。a.setScore(75) 修改的是 a 指到的 object，不會改到 b 指到的 object。

Q9Return Only

若 doubledScore 寫成下面這樣，呼叫後原本的 score 會變嗎？

public int doubledScore()
{
    return score * 2;
}

不會。這個 method 只計算並 return 一個值，沒有 assignment 改變 instance variable。

Q10Side Effect

若 doubleScore 寫成下面這樣，呼叫後原本的 score 會變嗎？

public void doubleScore()
{
    score = score * 2;
}

會。score = score * 2; 修改 receiver object 的 instance variable，所以是 side effect。

Q11Return and Mutate

以下 method 有 return value、side effect，還是兩者都有？

public int incrementAndGet()
{
    score++;
    return score;
}

兩者都有。score++ 改變 object state；return score; 回傳更新後的值。

Q12Void Method

void method 可以改變 object state 嗎？

可以。void 只代表沒有 return value，不代表不能有 side effect。

Q13Non-void Method

有 return type 的 method 一定沒有 side effect 嗎？

不一定。Method 可以同時修改 state 並 return value，題目要看 method body，不要只看 return type。

Q14Shadowing

以下 method 中，score 和 this.score 分別代表什麼？

public void setScore(int score)
{
    this.score = score;
}

score 是 parameter；this.score 是 receiver object 的 instance variable。

C. Pass-by-Value

Parameters 與 reference value 的 copy

重點句：object parameter 拿到的是 reference value 的 copy，不是 object 的 copy。

Q15Primitive Parameter

以下程式印出什麼？

public static void addOne(int x)
{
    x++;
}

int n = 5;
addOne(n);
System.out.println(n);

印出 5。x 是 n 的 value copy，改 x 不會改 caller 的 n。

Q16Object Parameter

以下程式印出什麼？

public static void changeScore(Student st)
{
    st.setScore(100);
}

Student s = new Student("Ada", 80);
changeScore(s);
System.out.println(s.getScore());

印出 100。st 和 s 當下指向同一個 object，透過 st mutation 會改到那個 object。

Q17Reassignment

以下程式印出什麼？

public static void replace(Student st)
{
    st = new Student("Ben", 50);
}

Student s = new Student("Ada", 80);
replace(s);
System.out.println(s.getScore());

印出 80。st = new Student(...) 只改 parameter variable st 指向哪裡，不會讓 caller 的 s 改指向新 object。

Q18Reference Copy

Object parameter 得到的是什麼的 copy？

得到的是 reference value 的 copy。兩個 reference variables 可以指到同一個 object，但它們本身仍是兩個不同的 variables。

Q19Reference Variable

Student s; 這個 variable 本身儲存整個 Student object 嗎？

不是。Reference variable 儲存的是可以找到 object 的 reference value；object 本身是由 new 建立的。

Q20Terminology

為什麼說 Java 不是 pass-by-reference？

因為 method 不能透過 reassignment parameter 來改變 caller 的 variable。Java 傳入的是 value；對 object variable 來說，那個 value 是 reference value。

Q21Trace Mutation

以下程式印出什麼？

public static void changeScore(Student st)
{
    st.setScore(st.getScore() + 5);
}

Student s = new Student("Ada", 80);
changeScore(s);
System.out.println(s.getScore());

印出 85。st 指到與 s 相同的 object，setScore mutation 會保留下來。

Q22Trace Reassignment

以下程式印出什麼？

public static void replaceThenChange(Student st)
{
    st = new Student("Ben", 50);
    st.setScore(99);
}

Student s = new Student("Ada", 80);
replaceThenChange(s);
System.out.println(s.getScore());

印出 80。新 object 和後面的 setScore(99) 都只影響 local parameter st 現在指到的 object。

D. Mutation vs Reassignment

先 mutation 還是先 reassignment，結果差很多

遇到 object parameter 題，逐行標記每個 variable 指向哪個 object。

Q23Mutation Then Reassignment

以下程式最後印出什麼？

public static void modify(Counter c)
{
    c.add(5);
    c = new Counter(100);
    c.add(1);
}

Counter a = new Counter(10);
modify(a);
System.out.println(a.getCount());

印出 15。第一行 c.add(5) 改到 a 的 object；之後 c 改指向新 object，c.add(1) 不影響 a。

Q24Reassignment Then Mutation

以下程式最後印出什麼？

public static void modify(Counter c)
{
    c = new Counter(100);
    c.add(1);
}

Counter a = new Counter(10);
modify(a);
System.out.println(a.getCount());

印出 10。parameter 先被 reassigned 到新 object，所以後面的 mutation 沒有改到 a 指的 object。

Q25Two Parameters

以下程式最後印出什麼？

public static void mix(Counter x, Counter y)
{
    x.add(2);
    y = x;
    y.add(3);
}

Counter a = new Counter(10);
Counter b = new Counter(20);
mix(a, b);
System.out.println(a.getCount() + " " + b.getCount());

印出 15 20。x.add(2) 讓 a 變 12；y = x 只改 local y，之後 y.add(3) 又改到 a，所以 a 變 15，b 不變。

Q26Parameter Assignments

以下 method 會交換 caller 的兩個 variables 嗎？

public static void swap(Counter x, Counter y)
{
    Counter temp = x;
    x = y;
    y = temp;
}

不會。這只交換 local parameter variables x 和 y 的 reference values，不會改 caller 的 variables。

Q27Mutating Two Objects

以下 method 會讓 caller 看到改變嗎？

public static void bonus(Player p, Player q)
{
    p.addPoints(10);
    q.addPoints(20);
}

會。這個 method 沒有 reassignment parameter，而是透過 references 呼叫 mutator methods，所以兩個 objects 的 state 都會被修改。

Q28Local New Object

以下程式建立的新 object，caller 能直接取得嗎？

public static void reset(Box b)
{
    b = new Box(0);
}

不能。新 object 的 reference 只存在 local parameter b 中；method 結束後 caller 的 variable 沒有被改指向新 object。

Q29Reset By Mutation

若真的要讓 caller 的 Box 變成 0，下列哪個做法比較合理？

public static void reset(Box b)
{
    b.setValue(0);
}

這個做法合理，前提是 Box 有 setValue mutator。它修改原本 object 的 state，而不是讓 local parameter 指向別的 object。

Q30Compile vs Logic

st = new Student("Ben", 50); 在 object parameter method 裡通常是 compile error 嗎？

通常不是 compile error，只是常見 logic error。它合法地改變 local parameter st，但不會改 caller 的 variable。

E. Aliasing / Object Return

Reference assignment、object return 與 alias

看到 = 時問自己：這是在複製 reference，還是在建立新 object？

Q31Alias Trace

以下程式印出什麼？

Counter a = new Counter(10);
Counter b = a;
b.add(3);
System.out.println(a.getCount());

印出 13。a 和 b 是 aliases，指向同一個 Counter object。

Q32Two New Objects

以下程式印出什麼？

Counter a = new Counter(10);
Counter b = new Counter(10);
b.add(3);
System.out.println(a.getCount());

印出 10。這裡有兩次 new，代表兩個不同 objects；改 b 不會改 a。

Q33Break Alias

以下程式印出什麼？

Counter a = new Counter(10);
Counter b = a;
b = new Counter(0);
b.add(4);
System.out.println(a.getCount());

印出 10。b = new Counter(0) 讓 b 改指向新 object，之後 b.add(4) 不影響 a。

Q34Return Existing Object

若 method 回傳 existing object，caller 可能和原本 object alias 嗎？

public Student getLeader()
{
    return leader;
}

可能。return leader; 回傳的是 reference value，caller 取得後可能與 field leader 指向同一個 object。

Q35Return New Object

以下 method 會回傳 existing object 還是 new object？

public Student makeCopy()
{
    return new Student(name, score);
}

回傳 new object。每次呼叫 new Student(...) 都會建立一個新的 object，通常不會和原本 receiver alias。

Q36Object Return Trace

以下程式印出什麼？

Student a = new Student("Ada", 80);
Student b = a.getSelf();
b.setScore(90);
System.out.println(a.getScore());

如果 getSelf 寫成 return this;，會印出 90。a 和 b 指向同一個 object。

Q37Copy Return Trace

以下程式印出什麼？

Student a = new Student("Ada", 80);
Student b = a.copy();
b.setScore(90);
System.out.println(a.getScore());

如果 copy 使用 return new Student(name, score);，會印出 80。b 是新 object，不會 alias a。

Q38Assignment Count

判斷是否 alias 時，最重要要數什麼？

通常要數 new 的次數與 reference assignment。一次 new 只建立一個 object；多個 variables 可以指向那同一個 object。

F. Contracts / null / private

Method contracts 與 object parameter 細節

AP 題常用 precondition / postcondition 描述 method 應該保證的行為。

Q39Precondition

Precondition 是什麼？

Precondition 是 caller 必須在呼叫 method 前保證為真的條件。例如 other != null 或 amount >= 0。

Q40Postcondition

Postcondition 是什麼？

Postcondition 是 method 執行完必須成立的結果，例如 receiver 的 score 增加、或回傳值代表兩個 objects 的比較結果。

Q41Private Access

同一個 class 的 instance method 可以讀取另一個同 class object 的 private fields 嗎？

public boolean hasSameScore(Student other)
{
    return score == other.score;
}

可以。Access control 是以 class 為單位，不是以 object 為單位；同一個 Student class 的 code 可以存取另一個 Student object 的 private field。

Q42null

若 other 可能是 null，以下 method 有什麼風險？

public boolean hasSameScore(Student other)
{
    return score == other.score;
}

若 other 是 null，other.score 會造成 NullPointerException。若沒有 precondition，就需要先檢查 other != null。

Q43Receiver vs Parameter

在 a.hasSameScore(b) 中，哪個是 receiver？哪個是 parameter object？

a 是 receiver object；b 的 reference value 被傳給 parameter other。

Q44Contract Reading

若 specification 說「does not modify either object」，你的 implementation 要避免什麼？

要避免修改 receiver object 或 parameter object 的 fields，也要避免呼叫會產生 mutation 的 mutator methods。

G. Coding / Trace

程式練習與 final tracing

最後六題把今天的觀念放進 AP-style method writing 與 trace。

Q45Write Method

為 Player 寫一個 hasMorePointsThan method。假設有 field private int points;，且 other 不為 null。

public boolean hasMorePointsThan(Player other)
{
    return points > other.points;
}

points 是 receiver 的 field；other.points 是 parameter object 的 field。

Q46Write Method

為 Student 寫 copyScoreTo(Student other)，把 receiver 的 score 複製到 other。假設 other 不為 null。

public void copyScoreTo(Student other)
{
    other.score = score;
}

這個 method 會 mutate parameter object other，但不改 receiver 的 score。

Q47Write Method

為 BankAccount 寫 transferTo(BankAccount other, double amount)。假設 other 不為 null、amount >= 0、餘額足夠。

public void transferTo(BankAccount other, double amount)
{
    balance -= amount;
    other.balance += amount;
}

Receiver 的 balance 減少，parameter object 的 balance 增加；這是兩個 objects 的 mutation。

Q48Object Return

為 Player 寫 higher(Player other)，回傳 points 較高的 existing object。假設 other 不為 null。

public Player higher(Player other)
{
    if (points >= other.points)
    {
        return this;
    }
    return other;
}

這會回傳 existing object 的 reference，caller 取得後可能和原本的 object alias。

Q49Transfer Trace

若 a balance 是 100，b balance 是 40，執行 a.transferTo(b, 25); 後兩者 balance 是多少？

a 是 receiver，所以 a 變 75；b 是 parameter object，所以 b 變 65。

Q50Final Challenge

最後挑戰：以下程式印出什麼？

public static void mystery(Counter x, Counter y)
{
    x.add(1);
    y = x;
    y.add(2);
    x = new Counter(50);
    x.add(3);
}

Counter a = new Counter(10);
Counter b = a;
mystery(a, b);
System.out.println(a.getCount());
System.out.println(b.getCount());

印出 13 再印出 13。一開始 a 與 b alias。x.add(1) 讓 object 變 11；y = x local 仍指同一個 object；y.add(2) 變 13。後面 x = new Counter(50) 只改 local x，不影響 a 或 b。
