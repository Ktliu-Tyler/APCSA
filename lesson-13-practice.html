A. Concepts

概念確認

先確認你能分辨 class、object、state 與 public interface。

Q1Class

Class 是什麼？

Class 是建立 object 的 blueprint，也是一種自訂 reference type。它定義 objects 會有什麼資料與行為。

Q2Object

Class 和 object 差在哪？

Class 是設計圖；object 是依照設計圖建立出的實體。不同 objects 可以使用同一份 class code，但保存不同 state。

Q3State

Object state 是什麼？

Object state 是 object 目前保存的資料，通常由 instance variables 描述。

Q4Class Name

Java class name 通常使用哪種命名習慣？

通常使用 PascalCase，例如 Student、BankAccount、ScoreTracker。

Q5Anatomy

一個基本 class 通常包含哪些部分？

Class declaration、instance variables、constructors、methods。本課先專注 instance variables 與 methods；constructors 下一課深入。

Q6Interface

Public interface 是什麼？

Public interface 是 class 對外開放的 public methods。其他 class 應該依賴這些 methods，而不是直接碰 private implementation。

B. Variables

Instance Variable / Local Variable / Parameter

AP 題常考「宣告在哪裡」與「這個變數保存多久」。

Q7Instance Variable

以下哪個是 instance variable？

public class Test
{
    private int x;

    public void method(int y)
    {
        int z = x + y;
    }
}

x 是 instance variable，因為它宣告在 class 裡、method 外。

Q8Parameter

上題中哪個是 parameter？

y 是 parameter，因為它出現在 method header 的括號中。

Q9Local Variable

上題中哪個是 local variable？

z 是 local variable，因為它宣告在 method body 裡。

Q10Default Value

Instance variable private int count; 的 default value 是什麼？

0。Instance variables 有 default values。

Q11Default Value

Instance variable private boolean active; 的 default value 是什麼？

false。

Q12Default Value

Instance variable private String name; 的 default value 是什麼？

null，因為 String 是 reference type。

Q13Local Variable

Local variable 是否也有 automatic default value？

沒有。Local variable 使用前必須明確初始化，否則會 compile error。

C. Encapsulation

Private / Public / Encapsulation

封裝的核心是 private state + controlled public methods。

Q14private

private field 的意思是什麼？

只有同一個 class 裡的程式碼可以直接存取這個 field。其他 class 通常要透過 public methods。

Q15public

public method 的意思是什麼？

其他 class 可以呼叫這個 method。它通常是 class public interface 的一部分。

Q16Encapsulation

為什麼 AP CSA class design 通常不鼓勵 public instance variables？

外部可以任意改資料，class 失去控制與 validation 的機會，容易破壞 object state。

Q17Validation

以下 setter 為什麼比直接 public field 好？

public void setScore(int newScore)
{
    if (newScore >= 0 && newScore <= 100)
    {
        score = newScore;
    }
}

它可以保證 score 只在 0 到 100 之間，讓 class 維護自己的合法狀態。

Q18Design

Encapsulation 是否等於「每個 field 都一定要 getter 和 setter」？

不是。Class 應該只開放合理操作。某些 field 不應被外部直接修改，甚至不需要 getter。

Q19Private Access

另一個 class 能不能直接執行 s.score = 100;，如果 score 是 private？

不能，會 compile error。外部應使用 s.setScore(100) 這類 public method。

D. Method Headers

Method Header 與 Return Type

看懂 method header 是閱讀 class 題的第一步。

Q20Header

在 public boolean isEligible(int minimumScore) 中，return type 是什麼？

boolean。

Q21Header

上題的 method name 是什麼？

isEligible。

Q22Parameter

上題的 parameter 是什麼？

int minimumScore，其中 minimumScore 是 parameter name。

Q23void

void return type 表示什麼？

表示 method 不回傳值給 caller。它可能修改 state 或印東西，但不能當成 expression value 使用。

Q24Return

以下 method 有什麼問題？

public int getName()
{
    return name;
}

如果 name 是 String，return type 應該是 String，不是 int。

Q25Return

以下 method 有什麼問題？

public int getScore()
{
    System.out.println(score);
}

Return type 是 int，method 必須 return 一個 int。印出不等於回傳。

Q26void

以下 method 有什麼問題？

public void getScore()
{
    return score;
}

void method 不應 return value。若要回傳 score，header 應改成 public int getScore()。

E. Accessor / Mutator

判斷 method 是否修改 state

不能只看名字，要看 method body。

Q27Accessor

哪個最像 accessor？

A. public void setScore(int s)
B. public int getScore()
C. public void increaseScore()
D. public void reset()

B。getScore() 通常回報 score，不修改 state。

Q28Mutator

public void deposit(double amount) 通常是 accessor 還是 mutator？

Mutator，因為它通常會修改 balance。

Q29Boolean Accessor

public boolean isAlive() 通常是什麼類型的 method？

Boolean accessor。它回傳 boolean 資訊，通常不修改 state。

Q30Derived Info

getArea() 直接計算 width * height，它還算 accessor 嗎？

算。Accessor 不一定只能 return field，也可以回報 derived information，只要不修改 state。

Q31Body

以下 method 是 accessor 還是 mutator？

public int getCount()
{
    count++;
    return count;
}

它修改了 count，所以不是純 accessor。判斷要看 body，不只看 method name。

Q32Mutator Return

Mutator 是否一定是 void？

不一定。Mutator 是看是否修改 state，不是只看 return type。有些 mutator 可能修改 state 後回傳新值。

F. Class Tracing

Object State Trace

Trace class 題時，列出每個 object 的 instance variables，再逐一套用 method body。

Q33Trace

假設 Counter 的 value 初始為 0，呼叫 increment() 一次後是多少？

public void increment()
{
    value++;
}

value 變成 1。

Q34Trace

若 value 已是 2，呼叫 reset() 後是多少？

public void reset()
{
    value = 0;
}

0。

Q35Trace

兩個不同 Counter objects 呼叫同一個 increment()，會共享同一個 value 嗎？

不會。每個 object 都有自己的 instance variables。

Q36Trace

以下 method 呼叫後 score 會變成多少？假設原本 score = 80。

public void addBonus(int bonus)
{
    score += bonus;
}

呼叫：addBonus(5)

85。

Q37Trace

以下 method 呼叫後 score 會變成多少？假設原本 score = 80。

public void setScore(int newScore)
{
    newScore = score;
}

呼叫：setScore(90)

score 仍是 80。Assignment 方向反了；這行只是把 parameter 改成 80。

Q38Trace

上題正確 setter 應該怎麼寫？

public void setScore(int newScore)
{
    score = newScore;
}
Q39Receiver

student1.getScore() 中 receiver object 是哪一個？

student1 是 receiver object，也就是這次 method call 正在操作或讀取的 object。

Q47Coding

為 BankAccount 寫出只接受正數的 deposit method。

private double balance;
public void deposit(double amount)
{
    if (amount > 0)
    {
        balance += amount;
    }
}
Q48Coding

為 BankAccount 寫出餘額足夠才提款的 withdraw method。

public void withdraw(double amount)
{
    if (amount > 0 && amount <= balance)
    {
        balance -= amount;
    }
}
Q49Design

在 Circle class 中，getArea() 應該放在 class 裡還是外面計算比較好？

通常放在 Circle class 裡，因為 Circle 擁有 radius，也最知道面積規則。

Q50Final Challenge

找出以下 class 的兩個設計問題，並修正。

public class Score
{
    public int value;

    public void setValue(int newValue)
    {
        newValue = value;
    }
}

問題 1：value 應該是 private。問題 2：assignment 方向反了。

public class Score
{
    private int value;

    public void setValue(int newValue)
    {
        value = newValue;
    }
}
