Java 編譯、執行與基礎語法

今天從 Java 的執行原理開始：source code 如何被 compiler 檢查，如何交給 JVM 執行， 接著再進入第一個程式、變數、資料型別、運算與輸出。

Opening Question

如果 Java 程式只是文字，電腦為什麼能執行？

先從這個問題開始想：你平常看到的程式碼其實是給人讀的文字， 但 CPU 不會直接理解 System.out.println("Hello") 這種句子。

先想一想

你覺得按下 Run 之後，中間可能發生哪些步驟？電腦是直接讀 Java 嗎？

Java 程式會先經過 compiler 檢查語法與型別，轉成 bytecode，再由 JVM 執行。 也就是：人寫 source code，compiler 檢查與轉換，JVM 負責執行。

Unit 1 的核心是理解「使用物件與方法」之前，Java 程式如何被建立、檢查、執行， 以及資料如何以變數的形式存在程式裡。

Big Picture

從問題到程式

程式設計不是直接打出一堆語法，而是把問題轉成可執行的步驟。這個順序能幫你避免「只記模板」。

Problem Algorithm Source Code Compiler Program Output

Algorithm 是解決問題的一系列明確步驟。它不一定是 Java， 可以先用中文、流程圖或 pseudo-code 表達，之後才翻成 source code。

Compiler

Compiler 的工作：先檢查，才讓程式繼續

Compiler 不是在「執行」程式，而是在執行前檢查程式是否符合 Java 的語法與型別規則。 只要 compiler 不通過，程式就不會進入真正執行階段。

Syntax

語法格式。例如括號、分號、大小寫、關鍵字位置。

Type Rule

型別規則。例如 int 不能直接存 "Hello"，boolean 不能存 1。

Compile-time Error

編譯階段就被抓到的錯誤，程式不會開始執行。

JVM

JVM 讓 Java 可以跨平台執行

Java 的 source code 通常會被編譯成 bytecode。Bytecode 不是直接給人閱讀的程式， 而是給 JVM 執行的中間形式。

因為不同作業系統可以安裝各自的 JVM，所以 Java 常被描述為「write once, run anywhere」的語言。

First Java Program

第一個 Java 程式：先看整體，不急著背每個字

Hello Java

public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, AP CSA!");
    }
}

public class Main 是線上 Java 執行器常用的外層 class。main 是程式開始執行的位置。println 會輸出一行文字。

Prediction Habit

AP CSA 的練習節奏：先預測，再執行

如果一開始只按 Run，很容易忽略程式真正的執行順序。AP CSA 很重視 code tracing： 在執行前，你要能推理出每一步做了什麼，以及最後會產生什麼 output。

先預測

這段程式會印出幾行？每一行的內容是什麼？如果把 println 改成 print，畫面會有什麼不同？

Statements

Statement：Java 中的一個完整指令

一個 Java statement 通常代表一個完整指令，大部分 statement 最後需要分號。 分號不是裝飾，它告訴 compiler：這個指令到這裡結束。

合法

int age = 18;
System.out.println(age);

錯誤

int age = 18
System.out.println(age);

通常錯誤會指向下一行或分號附近。除錯時要看該行，也要回頭看上一行是否少了分號、括號或引號。

Variables

Variable：有名字、有型別、能存 value 的位置

變數像一個貼了標籤的儲存格。Java 要求每個變數有明確型別，因為 compiler 需要知道哪些 value 可以放進去。

int
age
18

Data Type

int 說明這個變數可以存整數。

Identifier

age 是變數名稱，用來在程式中找到這個值。

Value

18 是目前被存入變數的資料。

Primitive Types

AP CSA 第一階段最重要的三種 primitive types

int

整數，沒有小數部分。

int score = 95;

double

可表示小數，也可存整數值的 floating-point 版本。

double height = 175.5;

boolean

只有 true 與 false，Java 不用 1/0 表示真假。

boolean ready = true;

String 用來表示文字，但它不是 primitive type，而是 reference type。之後進入 object 時會再正式比較。

Type Rules

Compiler 會檢查型別是否合理

Java 不只看 value 長得像什麼，還會看它的型別。5 和 "5" 對人來說都像五， 但對 Java 來說完全不同。

合法

double x = 5;
String text = "5";
boolean done = false;

不合法

int y = 5.0;
int z = "5";
boolean ok = 1;

Assignment

= 的意思：先算右邊，再存進左邊

數學中的 x = x + 1 不成立，但 Java 中的 x = x + 1; 很常見。 因為 Java 的 = 是 assignment，不是普通數學等號。

Assignment Trace

int x = 5;
System.out.println(x);

x = x + 1;
System.out.println(x);
5
6

第二次輸出前，右邊的 x + 1 先算成 6，再存回 x。

print() 與 println() 的差別

兩者都能輸出，但 println() 會在輸出後換行， print() 會停在同一行。

Arithmetic

運算優先順序：不要靠直覺猜 output

AP CSA 的選擇題常把簡短 expression 放進 println，你需要追蹤它最後會印出什麼。 先算括號，再算 * / %，最後算 + -。同優先順序通常由左到右。

先想一想

2 + 3 * 4 和 (2 + 3) * 4 結果一樣嗎？為什麼？

2 + 3 * 4 是 14。(2 + 3) * 4 是 20。括號會改變計算順序。

Integer Division

AP CSA 高頻陷阱：int / int 仍然是 int

Java 中，兩個整數相除時，小數部分會被直接移除，不會四捨五入。 這個觀念會在變數、method、FRQ、array index 計算中反覆出現。

先猜

double answer = 5 / 2; 的 answer 是 2.5 嗎？

不是。右邊 5 / 2 先做 integer division，得到 2，再存進 double，所以 answer 是 2.0。

Modulo

% 是餘數，不是百分比

% 會取得除法後剩下的 remainder。它常用於判斷奇偶數、取得個位數、拆解整數。

奇偶數

number % 2

結果是 0 時，代表 number 是偶數。

取得個位數

583 % 10

結果是 3。

移除個位數

583 / 10

integer division 後結果是 58。

String Concatenation

當 + 遇到文字，就可能不再是加法

如果 + 的其中一邊已經是 String，Java 會把另一邊接成文字。這是 AP CSA 很愛考的 output tracing。

Predict Before Run

System.out.println("A" + 2 + 3);
System.out.println(2 + 3 + "A");
System.out.println("A" + (2 + 3));
System.out.println("A" + 2 * 3 + 4);

Error Types

寫程式時，錯誤不是同一種東西

AP CSA 不只是看你會不會背語法，也會看你能不能分析程式行為。 一開始先把錯誤分成三類：syntax / compile-time error、runtime error、logic error。

Syntax Error

語法格式錯誤，通常屬於 compile-time error。

Runtime Error

程式能編譯，但執行到某一步時失敗。

Logic Error

程式能編譯、能執行，但答案或行為不符合題目要求。

重點不是「完全不要犯錯」，而是「看到錯誤時能分類」： compiler 抓到的是寫法規則，runtime 抓到的是執行中狀態，logic error 則要靠測試與推理找出來。

Syntax Error

Syntax Error：Java 語法格式不符合規則

Syntax 指的是程式語言的文法規則。就像英文句子有文法，Java 也有固定格式： 分號、括號、雙引號、大小寫、關鍵字位置都要符合規則。

Missing Semicolon

public class Main {
    public static void main(String[] args) {
        int score = 85
        System.out.println("Score: " + score);
    }
}

先想一想

這段程式還沒真正執行前，compiler 可能會抱怨哪裡？為什麼？

int score = 85 後面少了分號。分號代表 statement 結束。Compiler 看到下一行時，仍然以為上一個指令還沒結束。

修正：int score = 85;

Compile-time Error

Compile-time Error：編譯階段就不通過

Syntax error 是 compile-time error 的一種，但 compile-time error 不只包含語法。 Type mismatch、找不到變數、class 名稱錯誤，也都可能讓 compiler 不讓程式開始執行。

Type Mismatch

public class Main {
    public static void main(String[] args) {
        int age = "17";
        boolean passed = 1;

        System.out.println(age);
        System.out.println(passed);
    }
}

"17" 是 String，不能直接存進 int。1 是 int，Java 不會把它自動視為 true。

修正：int age = 17; 與 boolean passed = true;。

Runtime Error

Runtime Error：程式開始跑了，但中途失敗

Runtime 指的是程式正在執行的階段。Runtime error 的重點是： compiler 看得懂這段程式，但實際執行到某一步時，發現狀態不可能繼續。

Division by Zero

public class Main {
    public static void main(String[] args) {
        int total = 120;
        int groups = 0;

        int minutesPerGroup = total / groups;
        System.out.println(minutesPerGroup);
    }
}

這段程式語法正確、型別也正確，所以可以通過編譯。但執行 total / groups 時，groups 是 0， 整數除以 0 無法執行，因此發生 runtime error。

AP CSA 連結：未來學 array 時，存取不存在的 index 也是典型 runtime error。

Logic Error

Logic Error：最安靜，也最容易被忽略

Logic error 不一定會顯示紅色錯誤訊息。程式可以 compile，也可以 run， 但結果不符合題目要求。這種錯誤必須靠測試資料、trace code 與閱讀規格找出來。

Area Formula Bug

public class Main {
    public static void main(String[] args) {
        int length = 5;
        int width = 3;

        int area = length + width;
        System.out.println("Area: " + area);
    }
}

程式會輸出 Area: 8，但長方形面積應該是 length * width，也就是 15。 這不是 Java 語法問題，而是 algorithm 或 formula 寫錯。

Error Comparison

三種錯誤怎麼判斷？

English Term 中文理解 會 compile 嗎？ 會 run 嗎？ 找錯方向
Syntax / Compile-time Error 語法或型別規則不通過 No No 看分號、括號、引號、大小寫、型別
Runtime Error 執行到某一步時失敗 Yes Starts, then fails 看當下 value 是否造成不可能操作
Logic Error 能執行，但答案錯 Yes Yes 看題目規格、測試資料、algorithm

判斷錯誤時，先問自己：這段程式是「寫法錯」、「跑到一半錯」，還是「答案錯」。

Coding Practice

現場練習：三位數拆解

這個練習把 integer division 與 modulo 合在一起，是 AP CSA 很常見的 number manipulation 思維。

Challenge Starter

public class Main {
    public static void main(String[] args) {
        int number = 742;

        int hundreds = number / 100;
        int tens = (number / 10) % 10;
        int ones = number % 10;

        System.out.println("Hundreds: " + hundreds);
        System.out.println("Tens: " + tens);
        System.out.println("Ones: " + ones);
    }
}

/ 100 取得百位。/ 10 先移除個位，再 % 10 取出新的個位，也就是原本的十位。% 10 直接取得個位。

AP-style Check

快速檢核：先選答案，再揭曉

Consider the following code:

int a = 7;
int b = 2;
double result = a / b;

What value is stored in result?

A. 3 B. 3.0 C. 3.5 D. 4.0

答案是 B。a / b 先做 int / int，得到 3，再存進 double，變成 3.0。
