Instance Methods & References

今天把 object 真正動起來：method call 的 receiver object、return 與 side effect、 Java pass-by-value、object parameter、aliasing、mutation vs reassignment 與 method contract。

開啟 OneCompiler Lesson 15 課後練習

From Lesson 14

Constructor 建好 object，instance methods 讓 object 做事

new object state exists method call read or mutate state

接下來每一題都先問：這個 method 是在誰身上執行？

Receiver Object

Dot 左邊是 receiver object

Student s = new Student("Ada", 80);
System.out.println(s.getScore());
s.setScore(90);

s 是 receiver。Method body 裡沒有寫 object name 的 field，通常就是 receiver 的 field。

Quick Check

在 a.transferTo(b, 20) 中，誰是 receiver？誰是 parameter object？

a 是 receiver object；b 的 reference value 被傳給 method 的 parameter。

Same Method Code

同一份 method code，在不同 object 上讀不同 state

Student a = new Student("Ada", 80);
Student b = new Student("Ben", 92);

System.out.println(a.getScore()); // 80
System.out.println(b.getScore()); // 92

Receiver 不同，method 讀取的 instance variables 就不同。

Fields Inside Instance Methods

沒有特別標明 object 時，field 指 receiver 的 state

public int getScore()
{
    return score;
}

public void setScore(int newScore)
{
    score = newScore;
}

score 是 receiver object 的 instance variable。

Return Value

Return value 是交回 caller 的值

public int doubledScore()
{
    return score * 2;
}

這段 code 沒有改變 score，只是計算後回傳。

Side Effect

Side effect 是 method 改變了某個 object 的 state

public void doubleScore()
{
    score = score * 2;
}

這段 code 會 mutate receiver object。

Quick Check

這個 method 是 return only、side effect，還是兩者都有？

public int incrementAndGet()
{
    score++;
    return score;
}

兩者都有。score++ 修改 receiver state；return score; 回傳更新後的值。

Pass-by-Value

Java always passes by value

Primitive parameter

得到 primitive value 的 copy。

Object parameter

得到 reference value 的 copy。

這一句是 Lesson 15 的核心：reference value 被 copy，不是 object 被 copy。

Primitive Trace

改 parameter 不會改 caller 的 primitive variable

public static void addOne(int x)
{
    x++;
}

int n = 5;
addOne(n);
System.out.println(n); // 5

Reference Parameter

Object parameter 可以透過 reference mutation 同一個 object

caller variable copy reference value parameter variable same object

兩個 variables 不同，但可能指向同一個 object。

Object Parameter Mutation

Mutating through parameter is visible to caller

public static void changeScore(Student st)
{
    st.setScore(100);
}

Student s = new Student("Ada", 80);
changeScore(s);
System.out.println(s.getScore()); // 100

Parameter Reassignment

Reassigning the parameter is local

public static void replace(Student st)
{
    st = new Student("Ben", 50);
}

Student s = new Student("Ada", 80);
replace(s);
System.out.println(s.getScore()); // 80

st 改指向新 object，不代表 s 也改指向新 object。

Quick Check

這段最後印出什麼？

public static void modify(Counter c)
{
    c.add(5);
    c = new Counter(100);
    c.add(1);
}

Counter a = new Counter(10);
modify(a);
System.out.println(a.getCount());

15。第一個 mutation 改到 caller 的 object；reassignment 後的 mutation 只改到新 local object。

Aliasing

Reference assignment 會讓兩個 variables 指同一個 object

Counter a = new Counter(10);
Counter b = a;
b.add(3);
System.out.println(a.getCount()); // 13

a 和 b 是 aliases。

One new vs Two new

數 new，通常能看出有幾個 objects

Alias

Counter a = new Counter(10);
Counter b = a;

Separate Objects

Counter a = new Counter(10);
Counter b = new Counter(10);

Quick Check

這段最後印出什麼？

Counter a = new Counter(10);
Counter b = a;
b = new Counter(0);
b.add(4);
System.out.println(a.getCount());

10。b = new Counter(0) 後，b 不再指向 a 的 object。

Object Return

Returning an existing object returns a reference value

public Student getLeader()
{
    return leader;
}

Caller 可能拿到與 field 同一個 object 的 reference，形成 alias。

Return New Object

new in return 通常代表回傳新的 object

public Student copy()
{
    return new Student(name, score);
}

這種 copy method 通常用來避免 caller 直接 alias 原本 object。

Receiver and Object Parameter

Instance method 可以同時有 receiver 與另一個 object parameter

public void transferTo(BankAccount other, double amount)
{
    balance -= amount;
    other.balance += amount;
}

balance 是 receiver 的 balance；other.balance 是 parameter object 的 balance。

Quick Check

a.transferTo(b, 20) 後，誰減少？誰增加？

a 是 receiver，所以 a.balance 減少；b 是 parameter object，所以 b.balance 增加。

Private Access

Same class code can access another object's private fields

public boolean hasSameScore(Student other)
{
    return score == other.score;
}

Private 是 class-level access，不是 object-level access。

Method Contract

Precondition / Postcondition 幫你看懂 FRQ 要求

Precondition

Caller 呼叫前必須保證的條件。

other != null

Postcondition

Method 執行後必須成立的結果。

Balances have been updated.

Common Bugs

Lesson 15 最常見的錯誤

以為 object parameter 複製了整個 object。
以為 parameter reassignment 會改 caller variable。
忘記 a = b 可能讓兩個 variables alias。
只看 return type，沒有看 side effect。
分不清 receiver field 與 parameter object field。
忽略 null precondition。

Final Trace

最後挑戰：這段印出什麼？

public static void mystery(Counter x, Counter y)
{
    x.add(1);
    y = x;
    y.add(2);
    x = new Counter(50);
    x.add(3);
}

Counter a = new Counter(10);
Counter b = a;
mystery(a, b);
System.out.println(a.getCount());
System.out.println(b.getCount());

13 和 13。a 與 b alias；前兩次 mutation 都改同一個 object，最後 local x 改指向新 object。
