ArrayList algorithm tracing checklist

Core Problem

ArrayList Algorithm 真正難的是：size 和 index 會變

Array 的長度固定，所以 traversal 時 index 的意義通常很穩定。ArrayList 可以 add 和 remove，因此程式跑到一半時，size() 可能改變，後面元素的 index 也可能改變。

set(i, value)

取代元素，不改 size，不造成 index shift。

list.set(i, 0);

remove(i)

刪除元素，size 減 1，後方元素全部向左移。

list.remove(i);

add(i, value)

插入元素，size 加 1，原本位置之後的元素全部向右移。

list.add(i, value);
本課最重要的一句話： 只要在 traversal 中使用 add 或 remove，就要重新追蹤 list、index 和 size。

Traversal

ArrayList Traversal：用 size() 和 get(i)

ArrayList 不用 []，也沒有 .length。需要 index 時，用 traditional for； 只需要逐一讀取元素時，可以用 enhanced for。

traditional for traversal 
for (int i = 0; i < list.size(); i++)
{
    int value = list.get(i);
    System.out.println(value);
}
Loop適合情境不適合情境
traditional for需要 index、需要 set、可能 remove語法較長，但最彈性
enhanced for只讀取每個元素、sum/count/search需要 index、修改位置、add/remove
whileforward remove 後需要控制 i 是否增加read-only 題通常不需要
backward forremove all matching values需要保持從前到後處理順序時要小心

Read-Only Algorithms

Array 的基本 algorithm 幾乎可以搬到 ArrayList

如果 algorithm 只是讀取，不改變 list，通常只需要把 arr.length 改成 list.size()，把 arr[i] 改成 list.get(i)。

sum / count / max / search 
public static int sum(ArrayList<Integer> nums)
{
    int total = 0;
    for (int n : nums)
    {
        total += n;
    }
    return total;
}

public static int countAbove(ArrayList<Integer> nums, int threshold)
{
    int count = 0;
    for (int n : nums)
    {
        if (n > threshold)
        {
            count++;
        }
    }
    return count;
}

public static int indexOf(ArrayList<String> words, String target)
{
    for (int i = 0; i < words.size(); i++)
    {
        if (words.get(i).equals(target))
        {
            return i;
        }
    }
    return -1;
}
注意 empty list。 寫 max/min 時，若從 list.get(0) 開始，要確定題目保證 list 不是空的，或先處理空 list。

Filter

Filter Pattern 1：建立新的 List

如果題目說「return a list containing...」、「build a list...」、「do not modify the original list」， 最安全的做法是建立新的 ArrayList，把符合條件的元素加入新 list。

filtered copy pattern 
public static ArrayList<Integer> getPassingScores(ArrayList<Integer> scores)
{
    ArrayList<Integer> passing = new ArrayList<Integer>();

    for (int score : scores)
    {
        if (score >= 60)
        {
            passing.add(score);
        }
    }

    return passing;
}

保留偶數

if (n % 2 == 0)
{
    result.add(n);
}

保留長字串

if (word.length() >= minLen)
{
    result.add(word);
}

保留區間內資料

if (x >= low && x <= high)
{
    result.add(x);
}

建立新 list 的優點是沒有 index shift 問題，因為原本 list 沒有被刪除或插入。

Index Shift

Filter Pattern 2：直接 remove 原本 List

如果題目說「remove all... from the list」、「modify the given list」、「the original list should no longer contain...」， 就是要改原本 list。這時最常見錯誤是 forward loop 刪除後仍然直接 i++。

common forward remove bug 
for (int i = 0; i < nums.size(); i++)
{
    if (nums.get(i) < 0)
    {
        nums.remove(i);   // bug risk: next element shifts into index i
    }
}
StepListi發生什麼事
start[4, -2, -5, 7]1-2 符合 remove 條件
remove[4, -5, 7]1-5 從 index 2 左移到 index 1
loop update[4, -5, 7]2下一輪直接檢查 7，跳過 -5
連續符合刪除條件的元素最危險。 測 remove algorithm 時，務必測 [2, 2, 2]、[-1, -2] 這種連續案例。

Safe Removal

三種安全 remove 寫法

要刪除所有符合條件的元素，AP CSA 最推薦你能熟練 backward traversal。 forward while 也正確，但需要你明確控制 i 什麼時候增加。

1. Forward while

int i = 0;
while (i < list.size())
{
    if (shouldRemove(list.get(i)))
    {
        list.remove(i);
    }
    else
    {
        i++;
    }
}

remove 後不加 i，因為下一個元素已經移到目前 index。

2. Forward + i--

for (int i = 0; i < list.size(); i++)
{
    if (shouldRemove(list.get(i)))
    {
        list.remove(i);
        i--;
    }
}

用 i-- 抵消 for loop 結尾的 i++。

3. Backward traversal

for (int i = list.size() - 1; i >= 0; i--)
{
    if (shouldRemove(list.get(i)))
    {
        list.remove(i);
    }
}

從後面刪，左移只影響已經走過的右側位置。

recommended remove-all pattern 
public static void removeBelow(ArrayList<Integer> scores, int min)
{
    for (int i = scores.size() - 1; i >= 0; i--)
    {
        if (scores.get(i) < min)
        {
            scores.remove(i);
        }
    }
}
safe forward while pattern 
public static void removeNegatives(ArrayList<Integer> nums)
{
    int i = 0;
    while (i < nums.size())
    {
        if (nums.get(i) < 0)
        {
            nums.remove(i);
        }
        else
        {
            i++;
        }
    }
}

Enhanced For Limitations

Enhanced for 適合讀取，不適合結構性修改

Enhanced for 的優點是簡潔，但它沒有 index。當你需要使用 set(index,...)、 add、remove，或需要知道位置時，請改用 index-based loop。

任務Enhanced for 適合嗎？原因
sum / count適合只需要讀取每個 value
linear search value有時適合若只回傳 boolean；需要 index 時不適合
replace every negative with 0不適合需要 set(i, 0)
remove all invalid values不適合remove 會改變 list structure
insert while looping不適合add 會改變 size 和 index

不會真的改 list

for (int value : nums)
{
    value = 0;
}

value 是 loop variable 的 copy，不是 list 中的位置。

正確 replace

for (int i = 0; i < nums.size(); i++)
{
    nums.set(i, 0);
}

使用 set 才會改變指定 index 的元素。

Transform

set 用來 replace，不會改變 size

Transform 題型常見指令是「replace」、「change every」、「set invalid values to...」。 這類題不需要 backward traversal，因為 set 不會造成 index shift。

transform with set 
public static void replaceNegatives(ArrayList<Integer> nums)
{
    for (int i = 0; i < nums.size(); i++)
    {
        if (nums.get(i) < 0)
        {
            nums.set(i, 0);
        }
    }
}
OperationSizeIndex Shift常用 loop
set(i, value)不變沒有traditional for
remove(i)減 1後面左移backward for / while
add(i, value)加 1後面右移小心分析題目需求
add(value)加 1尾端新增通常用在 build new list

Data Analysis

ArrayList Data Analysis 題型

AP CSA 常把 ArrayList algorithm 包成資料分析題：成績、溫度、字串清單、物件清單。核心仍是 sum、count、average、max/min、search、filter、remove invalid data 的組合。

average and above-average count 
public static int countAboveAverage(ArrayList<Integer> scores)
{
    int total = 0;
    for (int score : scores)
    {
        total += score;
    }

    double average = (double) total / scores.size();

    int count = 0;
    for (int score : scores)
    {
        if (score > average)
        {
            count++;
        }
    }

    return count;
}
為什麼需要兩次 traversal？ 第一次先算 average；第二次才知道哪些 value 大於 average。
題目關鍵字常見做法
sum / totalaccumulator 從 0 開始
count values that...符合條件時 count++
average先 sum，再除以 size()
largest / smallest從第一個元素初始化 max/min
remove invalid readingsbackward traversal
return valid readingsfiltered copy

FRQ Strategy

寫 ArrayList FRQ 前先判斷 mutation 類型

ArrayList FRQ 最容易錯不是語法，而是你誤判題目到底要改原本 list，還是回傳新 list。 先圈出 prompt 的動詞，再選 loop。

Prompt words意思建議 pattern
return a new list原 list 通常不改filtered copy
remove all改原本 listbackward traversal
replace / change to改元素值，不改 sizeset with traditional for
count / sum / find只讀取enhanced for 或 traditional for
first index / last index需要 indextraditional for / backward for
FRQ contrast: remove vs return 
// Mutates original list.
public static void removeShortWords(ArrayList<String> words, int minLen)
{
    for (int i = words.size() - 1; i >= 0; i--)
    {
        if (words.get(i).length() < minLen)
        {
            words.remove(i);
        }
    }
}

// Returns a new list and leaves original list unchanged.
public static ArrayList<String> getLongWords(ArrayList<String> words, int minLen)
{
    ArrayList<String> result = new ArrayList<String>();
    for (String word : words)
    {
        if (word.length() >= minLen)
        {
            result.add(word);
        }
    }
    return result;
}

Common Errors

錯誤為什麼錯改法

enhanced for 中 remove結構性修改 list改用 index loop
for (int x : nums) x = 0;只改 loop variable，不改 list用 nums.set(i, 0)

Takeaways

本課檢核：看到題目時，你應該問的十件事

1. 這題是 read-only 嗎？若只是 sum/count/search，enhanced for 常常夠用。
2. 是否需要 index？需要位置、first/last index、replace by position，就用 traditional for。
3. 是否要改原本 list？prompt 說 remove/modify，通常要改原 list。
4. 是否要回傳新 list？prompt 說 return a list containing，通常建立新 list。
5. Body 裡有 remove 嗎？先想到 index shift。
6. Body 裡有 add(index,...) 嗎？後方元素會右移，size 會增加。
7. Body 裡只有 set 嗎？size 不變，照順序走通常安全。
8. 有連續符合條件的元素嗎？這是測 forward remove 是否有 bug 的關鍵。
9. List 可能是空的嗎？max/min 與 get(0) 要特別小心。
10. 每次 mutation 後有沒有重新 trace？寫出 current list、current index、current size。
Lesson 20 必背十五句

ArrayList traversal 用 size() 和 get(i)。

Enhanced for 適合 read-only traversal。

需要 index 時，用 traditional for。

set(i, value) 不改變 size。

remove(i) 會讓後方元素全部左移。

Forward remove 可能因 index shift 跳過元素。

連續符合 remove 條件的元素最容易暴露 bug。

Backward traversal 是 remove-all 題最穩定的 pattern。

Forward while remove 後不要增加 i。

Enhanced for 中不應做 structural modification。

改 loop variable 不等於改 list 元素。

Filter 可以修改原 list，也可以建立新 list。

Prompt 說 return new list 時，不要破壞原 list。

Prompt 說 remove from list 時，原 list 應該真的變短。

任何 add/remove tracing 題，都同步追蹤 list、index 與 size。
