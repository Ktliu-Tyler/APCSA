Constructors

今天學 object 建立時最重要的一步：constructor 如何初始化 state、如何和 new 搭配、如何處理 shadowing、default constructor 與 overloaded constructors。

Class 有 fields，但 object 剛建立時 fields 要怎麼初始化？

public class Student
{
    private String name;
    private int score;
}

Constructor 負責 object 建立時的 initial state。

Constructor Purpose

Initialize a newly created object

new object fields exist constructor runs initial state ready

Constructor 不是一般 method，它在 new 建 object 時被執行。

Basic Constructor

把 parameters 存進 instance variables

public class Student
{
    private String name;
    private int score;

    public Student(String studentName, int studentScore)
    {
        name = studentName;
        score = studentScore;
    }
}

Constructor Syntax

兩條超重要規則

Name matches classStudent class 的 constructor 叫 Student
No return type不能寫 void、int、String

public void Student(...) 是 method，不是 constructor。

Quick Check

哪一個是 Book constructor？

A. public void Book()
B. public Book()
C. public int Book()
D. public book()

B。Constructor name match class name，而且沒有 return type。

new Expression

new 建立 object 並呼叫 matching constructor

Student s = new Student("Amy", 95);
allocate object field defaults pass arguments run constructor return reference

Matching

Arguments 必須 match parameter list

public Student(String name, int score)
{
    this.name = name;
    this.score = score;
}

new Student("Amy", 95); // OK
new Student(95, "Amy"); // compile error

數量、順序、型別都要對。

Parameter Order

Parameter order 是 API 的一部分

String name第一個 argument 必須是名字
int score第二個 argument 必須是分數

AP FRQ 的 constructor header 必須照題目規格，不要自行調換。

Validation

Constructor 可以建立合法 initial state

public Student(String name, int score)
{
    this.name = name;

    if (score >= 0 && score <= 100)
    {
        this.score = score;
    }
    else
    {
        this.score = 0;
    }
}

Field Defaults

Constructor body 執行前，fields 已有 Java default values

int0
double0.0
booleanfalse
Stringnull
Local variables沒有同樣 default behavior
Design仍應照 specification 初始化

Shadowing

name = name 通常是 bug

private String name;

public Student(String name)
{
    name = name;
}

Parameter name shadows field name，所以這行把 parameter assign 給自己。

this.field

用 this.field 指明目前 object 的 field

public Student(String name, int score)
{
    this.name = name;
    this.score = score;
}
this.namecurrent object's field
nameconstructor parameter

Quick Trace

這段 constructor 後，field value 是多少？

private int value;

public Test(int value)
{
    value = value + 5;
}

Test t = new Test(8);

Field value 是 0。改的是 parameter，不是 field。

Fixed Trace

加上 this 後就不同

private int value;

public Test(int value)
{
    this.value = value + 5;
}

Test t = new Test(8);

Field value 是 13。

Default Constructor Rule

只有完全沒寫 constructor，compiler 才提供 no-arg default constructor

public class Thing
{
    private int x;
}

Thing t = new Thing(); // OK

有 methods 不影響；重點是有沒有 programmer-declared constructor。

No Automatic No-Arg

自己寫任何 constructor 後，no-arg 不再自動存在

public class Thing
{
    public Thing(int value)
    {
        x = value;
    }
}

new Thing(5); // OK
new Thing();  // compile error

Quick Check

這個 class 可以 new Thing() 嗎？

public class Thing
{
    private int x;

    public void setX(int value)
    {
        x = value;
    }
}

可以。它沒有宣告任何 constructor；setX 是 method，不是 constructor。

Overloaded Constructors

同一個 class 可以提供多種初始化方式

public Rectangle()
{
    width = 1;
    height = 1;
}

public Rectangle(double side)
{
    width = side;
    height = side;
}

public Rectangle(double width, double height)
{
    this.width = width;
    this.height = height;
}

Overload Signature

Parameter type list 不同才是 overload

ValidExample() and Example(int x)
InvalidBox(int width) and Box(int height)

Parameter names 不屬於 signature。

Constructor Trace

Trace 時看 arguments → parameters → fields

public NumberBox(int x)
{
    value = x + 5;
}

NumberBox b = new NumberBox(6);

11。Argument 6 進到 parameter x，再執行 value = x + 5。

Two Objects

每次 new 都初始化一個新的 object

Counter a = new Counter(5);
Counter b = new Counter(2);

a 和 b reference 不同 objects，各自有自己的 fields。

Design Question

哪些 initial state 應由 caller 提供？哪些由 class 決定？

public class ScoreTracker
{
    private String playerName;
    private int score;
    private int gamesPlayed;

    public ScoreTracker(String playerName)
    {
        this.playerName = playerName;
        score = 0;
        gamesPlayed = 0;
    }
}

Common Bugs

Constructor 常見錯誤

Constructor 加 void
Constructor name 和 class name 不同
name = name shadowing
Assignment 方向反了
以為 no-arg constructor 永遠存在
只改 parameter name 來 overload

Debug This

這段 constructor 有哪些問題？

public void Score(String name)
{
    name = name;
}

有 void，所以不是 constructor；name = name 也有 shadowing bug。應寫 public Score(String name) { this.name = name; }。
